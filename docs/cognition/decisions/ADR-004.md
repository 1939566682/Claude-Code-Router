# ADR-004 — Dev 协议/更新：维持与原版共用，串行使用为准

- 日期：2026-10-19
- 状态：已采纳
- 相关：INVARIANTS I-4、build/electron-builder.dev.cjs、ADR-001

## 背景

按你的要求，本仓不做同机双开。下文“协议/更新隔离不完全”若改成
ccr-dev:// 与独立 publish.repo，虽最彻底，但会改动导入链与自动更新
假设、增加合上游成本。ADR-001 已定“文件隔离必做、安装可选、端口/协议
按需”，本次复盘仍遵循之。

## 决策

1. 维持现状：`build/electron-builder.dev.cjs` 的 `protocols.schemes = ["ccr"]`
   与 `publish.repo = musistudio/claude-code-router` 不改，后装抢注册、
   同 appId 自动更新升回原版的边界在文档中显式说明。
2. 运行约束：原版与 Dev 版串行使用（先关一个再起另一个），`ccr://`
   抢注册与 \3456/3458\ \EADDRINUSE\ 在此约束下无感。
3. 若未来需真并存，再以独立 ADR 评估 `ccr-dev://` + 独立 `publish`
   （含迁移与合上游代价），不纳入本次批次。

## 后果

- 正：不改导入与发布面，合上游零增量冲突。
- 负：同机并存仍抢 \ccr://\ 与端口；Dev 同 appId 下会被原版更新覆盖，
  需手动关自动更新或切 repo——已在 \INVARIANTS.md:I-4\ 说明。

## 替代

- 现在就改 `ccr-dev://` + 独立 publish：彻底但未按你“不双开”的使用
  方式带来收益，已否决。

# ADR-001 — Dev 与原版隔离：文件隔离必做，安装/协议/端口按需隔离

- **日期**：2026-10-19
- **状态**：已采纳（已落地）
- **相关**：`INVARIANTS:I-1/I-2/I-4/I-5`、`CHANGELOG:v1-3`、`build/electron-builder.dev.cjs`

## 背景

本仓 `D:\Github\ccr-1939566682` 为 Dev 源码，Dev 产物外置 `D:\SoftWare\gateway\claude-code-router-dev`。需求是“随时在原版与 Dev 版间切换，不互相污染”。体检发现同 `APP_STORAGE_NAME=claude-code-router` 下 `%APPDATA%\claude-code-router` 的 `config.json/*.sqlite/certs/raw-trace-spool` 共用，`better-sqlite3` WAL 会 `SQLITE_BUSY`；`electron-builder.json:appId=com.claudecoderouter.desktop` 同名致 `requestSingleInstanceLock()` 互斥、安装覆盖。

## 决策

1. **必做（文件隔离）**：`packages/core/src/runtime/app-paths.ts:5` `APP_STORAGE_NAME` 改 `claude-code-router-dev` → Dev `%APPDATA%\claude-code-router-dev`，物理隔离 DB/配置（1 行，合上游时 1 行冲突）。
2. **可选（安装隔离）**：新建 `build/electron-builder.dev.cjs`，`appId→com.claudecoderouter.desktop.dev`、`productName→Claude Code Router Dev`、`artifactName→Claude-Code-Router-Dev_${version}.${ext}`、`directories.output→D:/SoftWare/gateway/claude-code-router-dev`，Dev 与原版 NSIS 可并存；`--dir` 免安装本身不写注册表，已足够串行场景。
3. **不做（端口/协议）**：默认 `3456/3458` 与 `ccr://` 保持原版一致，串行只跑一个时 `EADDRINUSE` 与协议抢注册无感；同机并存才需改。

## 后果

- 正：数据/安装分离，`win-unpacked` 直跑互不写；源码不被 `release/` 污染。
- 负：首次起 Dev 数据为空，需 `xcopy %APPDATA%\claude-code-router → claude-code-router-dev`；推 `1939566682` 会公开 Dev 身份，合上游需 rebase；`ccr://` 仍共用，后装抢注册；`electron-updater` 同 `appId` 会被当同一 App 升回原版，需关更新或换 `publish.repo`。

## 替代

- **环境变量隔离**（`CCR_INTERNAL_USER_DATA_DIR`）：不改源码即可文件隔离，但依赖启动脚本，易漏设。
- **全量换身份**（含端口/协议）：最彻底但改动面大、合上游成本高，串行场景收益有限，故不采纳。
